# 口径与定义 · 每个数字是什么意思（公开，永久保留，改动记版本）

> 每一条对外数字都能追回这里的某一条规则和某一个快照。规则本身也要有出处。

## 1. 中转站面板报价的读法（one-api / new-api 系）

来源：`/api/pricing`（公开，无需登录）+ `/api/status`（公开）。

| 字段 | 含义 | 出处 |
|---|---|---|
| `model_ratio` | 每百万输入 token 名义美元价 = `model_ratio × 2` | new-api `common/constants.go`：`QuotaPerUnit = 500*1000 // $0.002 / 1K tokens` |
| `completion_ratio` | 输出价 = 输入价 × completion_ratio | 同上 |
| `group_ratio[group]` | 分组倍率，乘在名义价上 | `/api/pricing` 返回 |
| `quota_type=0` | 按 token（用上两行） | new-api `model/pricing.go:389` |
| `quota_type=1` | 按次，`model_price` 为每次名义美元 | new-api `model/pricing.go:384` |
| `quota_type=2` | **按秒**，`model_price` 为每秒名义美元。上游无此类型，为分支版自加 | toapis 前端渲染代码：`1===quota_type ? "/req" : 2===quota_type ? "/s"` |
| `model_type` | 0 视频 / 1 图像 / 2 文本 / 3 音频 | toapis 前端：`{video:0,image:1,chat:2,audio:3}` |
| `pricing_version` | 全站定价哈希，任一模型变动即变 | `/api/pricing` 返回；用于变更检测，比对时剔除 |

## 2. 名义美元 → 用户实付

面板价是「名义美元」。用户实付取决于充值时 $1 名义额度收多少钱：

```
实付美元 = 名义美元 × price ÷ USD/CNY 汇率          （人民币充值通道）
实付美元 = 名义美元 × stripe_unit_price              （Stripe 美元通道）
```

| 字段 | 出处 |
|---|---|
| `price` = 每 $1 名义额度收多少人民币，默认 7.3 | new-api `setting/operation_setting/payment_setting_old.go:16`；`controller/topup.go:175`：`payMoney = amount × Price × topupGroupRatio × discount` |
| `stripe_unit_price` 默认 8.0，等于默认视为未配置 | new-api `setting/payment_stripe.go:6`；`controller/topup_stripe.go:441` |
| 汇率 | 独立证据源，每次快照（open.er-api.com） |

**两条通道价差 ≥1.5 倍时，句子里注明「按人民币通道计」并附 Stripe 价。**
**拿不到的两个因子**（`topupGroupRatio`、`AmountDiscount`）只会让实付更低 → 我们算出的比率是**上界**，方向保守。

## 3. 成本下限比率

```
比率 = 中转站实付价 ÷ 本站已收录同模型最低公开渠道价
```

- 分母取 official + marketplace（OpenRouter 转载供应商标价）里的**最低值**；多档（空闲/高峰、分辩率）取最低档 → 比率偏高，宁少标不多标
- 分档：<0.15 无补贴假设下数学上不可持续 · 0.15–0.40 显著低于常见批量折扣 · 0.40–0.75 可由批量折扣解释 · 0.75–1.25 与公开价接近 · 1.25–3 高于公开价 · ≥3 显著高于
- **极端值闸门**：比率 <0.05 或 >5 且换算链任一环缺证据 → 不发布，先核对。链条齐全则放行（闸门防的是我算错，不是防事实极端）
- **图像 / 视频的三个补充口径（2026-09-14）**：① 时长——站方模型名里写了单次时长（如 `_10`、`-8s`）就按它折算，否则用该族默认时长并注明；② 分辩率——站方名字里的 480p/720p/1080p/2K 或 1080*1920 这类尺寸，优先匹配官方同一档的价格，官方没有该档才取最低档并注明"比率偏高"；③ 族归属——按品牌名先判（Wan、HappyHorse、Vidu…），"t2v / i2v" 这类通用词只在没有品牌名时才用；此前它们被错归到海螺族，已修正。多模态报价比率 <5% 或 >500% 的行一律标"待核"，不比对不进榜。
- 模型名归一 v2：去厂商前缀、去 `:batch/:free`、去日期尾缀、去 `-official` 等中转自加后缀、数字间 `-`→`.`

## 6. 出站入口 `/go/<域名>` 与推广参数

**入口**：每个收录站的事实页和比价表都有「前往」。跳转经本站 `/go/<域名>` 中转（Cloudflare Worker，`site/worker_go.js`），
302 到 `relay_candidate.site_url`。只记按站点击数，**不存 IP / UA / Referer**；`Referrer-Policy: no-referrer`。

**目标地址守卫**：站方 `/api/status` 的 `server_address` 只在「https + 公网主机名 + 与收录域同注册域」时采用，
否则回退 `https://<域名>/`（实测 helpcoder.cc 配的是 `http://localhost:3000/`）。

**推广参数（默认关闭，`REFERRAL_ENABLED=0`）**。若启用，硬约束写死在代码里：
1. 排序、判读、任何比率永不读 `referral_url` 字段（承诺一）
2. 带推广参数的入口渲染为「广告」标识，`rel="sponsored nofollow"`（承诺二 / 《互联网广告管理办法》）
3. **检测报告页、质量测量页不得出现本入口**，只在事实页与比价表的「前往」列（承诺四）
4. 每站点击数公开；推广收入占比按季公开（承诺五）
5. 只对有官方推广计划的站配置 `referral_url`，且该站的检测结论照常发布、不因推广关系调整措辞

**未决**：从被测中转站拿返佣，与「不收被测方的钱」的承诺冲突，是 CCTest 的路。字段和开关已备好，是否打开是产品决策，不是技术决策。


## 7. 多模态（图像 / 视频）比对

**分类**：`core/modality.py` 按模型名分 image / video / audio / other（族谱正则）。名字含 image/img/t2i/i2i 且不含 video/i2v/t2v 的先按图像判；audio/voice/lip-sync 归音频。用 toapis `model_type` 真实标签验证，97%。

**单位换算**：
- 中转按秒（`quota_type=2`）vs 官方按秒：直接比
- 中转按次 vs 官方按秒：`每秒实付 = 每次实付 ÷ 该族默认单次时长`。默认时长表（来源各家 API 文档默认参数）：Veo 8s（4/6/8）、Kling 5s（5/10）、Hailuo/H3 6s（6/10）、Seedance 5s（5/10）、Vidu 4s（4/8）、Wan 5s、Sora 10s。**每一句结论都写明"按默认 N 秒折算；若该站一次含更长时长，比率偏高"**
- 图像：中转按次 vs 官方按张。官方取最低分辩率档作分母；FLUX 官方按百万像素，1 张按 1MP（≈1024×1024）
- 全部取保守方向：假设只会让比率偏高，宁少标不多标

**参考价出处**：Google Veo / Nano Banana（ai.google.dev 定价页）、Kling 视频与图像（kling.ai/dev/pricing 嵌入 JSON）、MiniMax H3（platform.minimax.io 按量计费页）、BFL FLUX（bfl.ai/pricing）。
**未接入**：Seedance / Seedream、Vidu、Wan / Qwen-Image（页面前端渲染）、Sora / GPT Image（OpenAI 403）、Midjourney（无按次 API 价）—— 只列报价，不出比率。

**旧版本提示**：站方卖 Kling v1/v2、Veo 2、Hailuo 02 而参考为新版官方价时，句子注明（旧版官方价通常更低 → 比率偏高）。

**媒体站级闸**：某站媒体行比率中位 <0.01 或 >30 → 整站「计价方式待核」不出比率；实付 <$0.0005 的行视为占位价跳过。

## 8. 一致性探针（T1 指纹）

- **前提**：只对本站用自己注册的 Key 能调用的中转站做；Key 只存本机 `data/keys.env`，不进仓库、不进日志、不进页面。
- **做法**：对该站声明的每个模型，发一组固定探针请求（内容固定、跨站跨天不变，具体构成不公开以防针对性应对），只要极少的输出 token。记录返回的用量计数、回显的模型名、首字节延迟、HTTP 状态。每站每模型成本以厘计。
- **比对**：同一模型、同一探针，不同分词器切出的 token 数不同。当足够多的渠道对同一模型报出完全相同的一组计数时，视为该模型的**共识簇**；某渠道计数与共识簇不同 → 记「计数与同模型其他渠道不一致」；共识渠道不足 → 记「共识样本不足」，不下结论。回显模型名与请求不符 → 附注「回显模型名不同」。
- **措辞**：这是**一致性测量**，不是真伪判定；不出现任何指控性词汇。页面只写 一致 / 不一致 / 样本不足 + 成功条数 + 日期。
- **边界**：中转站可能对同一模型接了多个上游并随机分流，一轮探针只覆盖当时命中的那条；按次计价的模型不测。
- **数据**：`probe_t1` 表（每条一行）；导出时取最近 7 天每个 站×模型×探针 的最新一条参与共识；`data_v2.json` 里每行带 `probe{status, ok, n, echo, peers, ts}`。


## 9. 数据核查（错误不能靠用户发现）

每晚拉完价、出榜之前，自动跑四项核查；命中的行标"待核"，不参与比对、不进任何榜，直到我们核对原始条目后放行或修正解析器：

- **字段漂移**：某站的定价接口出现我们不认识的字段时，列出来人工看一眼。2026-09-06 就是这样发现有站把"按秒计费"写在附加字段里、被我们当成按次的。
- **单位提示**：按次计价的图像 / 视频报价，原始条目文字里却写着"每秒 / 按秒 / per-second" → 待核。
- **单位嫌疑**（2026-09-20 新增）：面板没写计价单位、我们按惯例当成"按次"的图像 / 视频报价，如果"按次读"低于同型号官方参考价的 25%（异常低），而"按每秒读"正好落回 40%–150%（正常），就判为单位嫌疑：该行待核，不进比对与榜单，并由站长通知去问对方的实际口径。这是嫌疑不是结论，我们不替站方改单位；站方回复后按原文记录，并把修正署名写进修正日志。规则来源：2026-09-20 relaydance.com 站长指出我们把按秒计费的超分接口读成了按次。
- **后处理接口不进生成族**（2026-09-20 新增）：超分、增强、插帧、修复这类对已有图像 / 视频做后处理的接口，不是生成模型，不计入生成模型族的价格比对与中位数。
- **价格孤点**：同一族里某站的每秒（图像：每张）实付低于全族中位的 35%，又比第二便宜的站低一半以上 → 待核，直到出现第二家相近价。
- **榜首差距**：任何一张多模态榜的榜首若比第二名低 40% 以上且只此一家，先不进榜。榜页会写明本期有几条待核。

放行记录带日期与备注。这套规则不追求"零漏网"，只保证：单独一家的异常低价不会自动坐上榜首。


## 10. 收录与退场

**怎么找到新站（五条通道，全部自动、每天跑）**

1. **证书透明度日志**：新站上线前要申请 HTTPS 证书，证书进公开日志。我们每小时读一段日志，只探测第一次出现的域名。这是最早的信号，但命中率很低。
2. **名录与导航站**：aiapirank、howtok、公益导航等公开名录，每周重抓一遍，取新增域名。
3. **公开社区**：NodeLoc、V2EX 的公开接口里含"中转 / 公益站 / new-api"等词的帖子，取正文里的域名。linux.do 需要邀请注册且拦截匿名访问，不接。
4. **邻接扩散**：新入池的站页面上的外链和别名域，中转站之间互相引流，新站常先出现在老站的链接里。
5. **用户提交**：登录后在总表页填域名，当晚处理。只收域名，不收推广参数。
6. **Telegram 公开频道**：中转站几乎都有频道发上新与优惠。从已收录站首页与社区帖子里收集频道名，读公开预览页（不需要账号，只显示公开频道），从消息文字抽域名。
7. **内容指纹**：不跑开源面板的自研聚合站（kie.ai 一类）面板指纹抓不到；对能连上但没有面板签名的域，读少量公开页面，同一页提及 ≥4 家互相竞争厂商的模型族才算"多厂商聚合"并收录。这只是一个可核验的计数，不给"是不是中转站"的标签。

**怎么确认是中转站（一次普通 GET）**：绝大多数中转站跑两类开源面板：按量计费的 one-api / new-api 一族，和订阅套餐制的 Sub2API 一族（2026 年 Claude Code、Codex 订阅中转的主流面板），各有固定形状的公开状态接口。Sub2API 站按套餐售卖、价格需登录，本站只列能公开核实的事实（面板类型、注册是否开放、登录方式、可达率），不做套餐比价。命中即收录为"已确认"；只返回鉴权错误、没有面板签名的记为"弱指纹"，不进总表，之后再试一次定价接口，拉到报价才升级。我们不做端口扫描、不绕过任何技术措施、每个域名只探一次；厂商官方域与基础设施域（openai.com、claude.ai、cloudflare.com 等）直接排除，不会被当成中转站。

**收录之后的持续验证**：每小时一次可达探测（记可用与首字节延迟）；每天拉一次定价接口；每天探一次新用户注册入口（关闭的不进榜）；有 Key 的站每天跑一致性探针与能力抽样。

**退场**：连续 7 天、至少 100 次探测一次都没连上，标为"7 天未连通"：页面保留，不进任何榜、不计入可达统计。之后再连上会自动恢复。


## 11. 司南 Token 价格指数

每天发布"中国中转市场每百万 Token 多少钱"。样本是已确认中转站里、不在"计价方式待核"的站，对每个最新两代主流模型的每百万输出 token 实付价（与账本同一算法：面板名义价 × 充值比例 ÷ 汇率）。

- **每模型每日**：跨站中位数、25/75 分位、站数；当天不足 15 个站报价的模型不计入。
- **折价率** = 市场中位实付 ÷ 官方参考价。按官方参考价分三档：旗舰 ≥$20/M、中档 $2–20/M、快速 <$2/M；档与全市场的折价率、中位价取各模型的中位数。这是当日快照，会受模型进出影响。
- **点位**：2026-09-02 = 100，按相邻两日共有模型中位价环比的几何平均链式相乘，不受模型进出影响，用来看涨跌。
- **历史**：按每条报价的有效区间逐日重建当天收盘状态。
- 数据文件 `/price-index.json` 每日更新；引用请写"司南 Token 价格指数（Sinan Token Price Index），compute.sinanlab.com"。

**任务成本**：能力抽样每天对各模型发同一套 30 道小题，记录每题实际消耗的输入 / 输出 token，跨渠道取中位，乘上官方价与市场中位价，得到"同一件事各模型花多少钱"。

## 13. 成本下限的换算假设（公开）

第 3 节的"<0.15 数学上不可持续"是一条算术分档线，这里把它背后的假设摊开，方便核对与反驳。

**为什么是 15%**：中转市场最常见的定价方式是"名义价照抄官方美元价，充值按 1 元人民币换 1 美元额度"。按汇率 6.7 折算，实付正好是官方价的 14.8%。也就是说，15% 这条线把"1 元换 1 美元"这类站整体划进了"低于成本下限"。它们能不能长期这样卖，取决于上游是什么，我们不推测，只标出来。

**闭源模型（GPT、Claude、Gemini 一类）**：没有开源权重，任何渠道最终都要向厂商按 API 价付费。公开可查的企业折扣通常不超过五成，因此长期低于官方价 40% 的报价，在"合规向厂商采购"这个假设下算不平。这是 0.15–0.40 档标"显著低于常见批量折扣"的依据。

**开源模型（DeepSeek、Qwen、GLM、Kimi 一类）**：可以自己租卡跑，成本地板由算力决定。粗算公式：

```
每百万输出 token 成本 ≈ 单卡时租 ÷ (单卡每秒吞吐 × 3600 ÷ 1,000,000)
```

单卡时租取第 12 节算力租赁账本里的 Vast.ai 按需中位价；吞吐是最大的不确定项，取决于模型规模、量化、并发与显存，同一张卡从几百到几千 token/秒都可能。举例：H100 按 $3/时、高并发下 3,000 token/秒，成本约 $0.28 / 百万 token；4090 按 $0.47/时、800 token/秒，约 $0.16 / 百万 token。这些只说明数量级：开源快速档模型的官方价（几分到几毛美元）本身就贴近算力成本，所以中转站在这一档很少能低于官方价，指数里快速档折价率接近 100% 与此一致。

**我们不做的事**：不用这套公式给任何单站算"亏不亏"。吞吐假设一变结论就变，所以站内只用公开渠道价做分母、只报比率，算力成本仅作为理解分档的背景。

## 14. 经司南核验（站长可申请，免费）

- **申请**：站长登录后在 `/verify` 提交域名与联系方式，再把一把小额 Key（余额约 20 元，只开放要核验的模型）发到 hello@sinanlab.com。Key 只存本机 `data/keys.env`，不进网页、不进仓库。
- **条件（全部满足，连续 7 天）**：一致性探针至少 5 个模型有结果且全部"一致"、7 天内没有"不一致"；能力抽样答对数不低于同模型多渠道中位数减 2；7 天可达率 ≥ 99%；新用户注册开放。
- **发放与摘除**：条件由 `site/export_data.py` 每晚按数据自动判定，写入 `data_v2.json` 每站的 `verified` 字段。满足即在站点页显示"经司南核验"标识并生成 `/badge/verified/<域名>.svg`；任何一天不满足自动摘除，满足后自动恢复。人工不能加也不能免。
- **含义**：只陈述"这几项测量在这段时间通过"，不是推荐或担保。不收费、不接受付费加速、不因是否申请改变任何榜的排序。

## 15. 月报（先月度，季度与年度再叠加）

- **周期**：每月一期，从 2026 年 9 月创刊。当月每天重算并标"滚动更新"，次月 1 日定稿标"定稿"，永久链接 `/report/YYYY-MM`，原始数据 `/report/YYYY-MM.json`。
- **来源**：全部来自站内每日测量的存档（每日快照、价格指数、账本、审计表），不加入任何人工数字。
- **五个部分**：价格（Token 价格指数、期内中位价涨跌最多的模型）、市场结构（面板家族、注册开放度、移除与失联）、可达与检测（可达分布、探针与能力抽样、数据核查放行情况）、图像与视频、算力成本层。
- **引用**：每页底部给中英文引用格式；转载请注明"数据：司南实验室 compute.sinanlab.com"。
- **数字与分析分开**：数字部分（规模、价格、可达、检测、多模态、算力，以及国产/海外折价、分档区间分布、充值比例分布、面板家族、登录生态、变价方向、开源模型算力下限等结构性指标）由 `site/monthly_report.py` 每晚自动重算；分析与判断由司南实验室按期撰写，存为 `site/reports/<月份>.analysis.md`，只基于当期测量，不含对任何渠道的推荐。分析文字随定稿一并更新；两者在页面上分节并列，读者可以只信数字、不采纳判断。

## 16. 榜单与指数的呈现规则（2026-09-15 起）

- **位次变动**：每张站点榜的名次旁标与上一期同一张榜的比较（↑n / ↓n / 新 / ＝）。比较对象是上一期 JSON 里的同名榜，门槛变化导致的进出也如实标"新"。
- **模型供给榜**：按"有有效报价的站数"排模型。站数是供给侧的市场份额（多少站在卖），不是需求侧的用量份额；我们没有用量数据，也不估算。附市场中位价 7 天变化与一致性探针计数（只对有 Key 的站）。
- **站间离散度**：某模型在各站实付价的 25–75 分位跨度 ÷ 中位。分档与全市场取各模型离散度的中位数。数值越大，同一模型在不同站的价差越大，比价越有价值；它不是质量指标。
- **变化窗口**：指数点位同时给 7 天与 30 天变化；不足 30 天时用序列首日。
- **出刊节律**：司南榜每周一北京时间早间出刊，窗口为上周一到周日；指数每日；月报当月每日滚动、次月 1 日定稿。任何一期的永久链接与 JSON 不再改动，修正只以追加修正记录的方式进行。
